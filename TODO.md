# TON Shop Bot delivery checklist

- [x] **Hybrid Telegram experience:** The existing Telegram bot remains fully operational with its command menu and verified payment monitor, and now launches the authenticated customer and admin Mini Apps.
- [x] **Personal market verification phrase:** Users can create a personal phrase with `/setphrase` and display it with `/verify_market`. The database stores a salted hash and encrypted copy rather than plaintext, and the guidance tells users to verify the exact official bot username/profile and never reveal the phrase to another bot, website, support agent, or payment agent.
- [x] **Physical product catalogue:** Customers can browse products with descriptions, images, GBP prices, and current stock quantities, and open product detail views.
- [x] **GBP catalogue pricing:** Admin product prices are entered and stored in GBP pence; customers see GBP in the catalogue and basket. The exact TON/BTC/LTC amount is calculated and shown only after the customer chooses a payment method at checkout.
- [x] **Editable placeholder catalogue:** On first startup the database seeds 20 root categories, 60 subcategories, and 240 clearly labelled placeholder products with GBP prices, SKUs, emerald/gold placeholder images, stock, active state, and featured state. Customers browse categories before products, and inactive products are hidden.
- [x] **Bulk catalogue management:** Admin can export the catalogue, download a CSV template, import CSV updates matched by SKU, create/rename categories, move products by changing category columns, and update price, stock, image, active, and featured fields without modifying code.
- [x] **Customer Telegram Mini App:** A mobile-first emerald-and-gold Mini App is served at `/miniapp`, validates Telegram initData server-side, reads the shared catalogue, supports category browsing, search, product cards, basket quantities, GBP totals, and checkout into the existing verified payment flow.
- [x] **Customer Mini App discovery and product details:** Featured products and newest products are shown in dedicated sections. Product detail pages show the image, description, GBP price, stock, quantity selector, add-to-basket action, and wishlist action.
- [x] **Persistent wishlist:** Authenticated wishlist IDs are stored in SQLite per Telegram user and exposed through protected read/toggle APIs; the Mini App supports saving and viewing wishlist products.
- [x] **Protected admin dashboard:** `/admin-dashboard` is protected by server-side Telegram authentication and the configured admin Telegram ID. It supports product edits, inventory/active/featured changes, category creation/renaming, image uploads, and shares the same SQLite data as the bot.
- [x] **Admin bot editor:** The protected dashboard can edit welcome/help copy, customer/admin launch-button labels, and all visible Telegram command descriptions. Settings persist in SQLite, apply to bot messages immediately, and update Telegram's command menu through the live bot session. Bot tokens, admin identity, payment wallets, and blockchain verification settings remain non-editable protected configuration.
- [x] **Shopping cart:** Customers can add products, increase and decrease quantities, remove items, clear the cart, see totals, and stay within current stock limits.
- [x] **Checkout and delivery:** Checkout reviews the order, lets the customer choose TON, Bitcoin, or Litecoin when configured, collects and validates the delivery address, rechecks stock, and creates a pending order.
- [x] **TON payment flow:** The bot presents the configured recipient wallet, exact nanoTON payment amount, and an order-specific transfer reference.
- [x] **Bitcoin and Litecoin payment flow:** The bot obtains a live TON/BTC/LTC quote, stores an exact BTC/LTC atomic amount with a short expiry, presents the configured network wallet, and requires the customer to submit the transaction ID for verification.
- [x] **Secure automated multi-chain verification:** A submitted transaction ID alone never marks an order paid. TON checks recipient, exact amount, successful execution, and masterchain finality. BTC/LTC checks the real transaction outputs, recipient wallet, exact atomic amount, confirmation threshold, and transaction-ID uniqueness.
- [x] **Order history and tracking:** Customers can see previous orders and payment/fulfilment status in Telegram.
- [x] **Admin product controls:** Admin-only flows support adding, editing, and deleting catalogue items, including descriptions, images, GBP prices, and stock quantities.
- [x] **Inventory management:** Inventory changes are admin-only and stock is rechecked before order creation and payment acceptance; cancelling an unpaid order releases its reservation.
- [x] **Admin order management:** Admin can review orders, inspect verified payment status, adjust fulfilment status, and cannot manually accept a transaction hash.
- [x] **SQLite and secret-safe operations:** SQLite persistence is used; Telegram bot token, admin ID, TON/BTC/LTC wallets, and optional blockchain API key are environment variables; source and logs do not expose secrets.
- [ ] **Cloud operation:** The repository includes container deployment and health-check configuration, but continuous always-on hosting is blocked because the current account requires membership for the reserved hosting mode. The project is ready to publish after that hosting requirement is resolved.
